pi-canvas lets a pi agent answer with a picture instead of a wall of text — a diagram, a chart, a diff, a board — as one self-contained HTML file. You mark it up in the browser; your notes flow straight back into the agent's session.

At a glance

Draw

artifact new writes a skeleton; the agent fills it with JSON data components. artifact check validates and screenshots it.

Annotate

artifact session serves it locally with a note layer. Select text, ⌥-click a diagram node, pin a diff line.

Return

Send via Pi delivers every note to the agent, which fixes things and replies — the page updates live.

This page is itself a pi-canvas artifact, built only from the components below. Everything is interactive: hover, sort, drag, expand.

How it works

The feedback loop

Notes are one of four kinds, and anchor to whatever you pointed at:

KindUse it forAnchor examples
❓ question"why is this like that?"selected text · a heading
📝 notecontext the agent should knowa flow node · a chart bar
✏️ change"do this differently"a diff line → path:line
✅ approvesign-off on a parta card · the whole page

Local pre-PR review

artifact review renders your branch — committed, uncommitted and untracked changes vs. the merge base — with the agent's verdict and findings on top. Pin a line to leave a note; re-running refreshes the diff and keeps every note.

artifact review review-api-auth --repo ../api --base origin/main
artifact check review-api-auth
artifact session review-api-auth --detach --no-open
artifact session review-api-auth --url     # open this, annotate, Send via Pi
artifact new explainer rate-limits --title "How rate limiting works" --subject api
# fill the content region, then
artifact check rate-limits && artifact open rate-limits
artifact notes rate-limits                 # everything, as Markdown
artifact reply rate-limits n3k2x "Split into two steps, see diagram"
artifact resolve rate-limits n3k2x

Anatomy of a component

This is all an agent writes for the diagram at the top of How it works:

<script type="application/json" data-component="flow">
{"direction":"lr",
 "nodes":[{"id":"a","label":"Agent"},
          {"id":"cli","label":"artifact CLI","tone":"accent"}],
 "edges":[{"from":"a","to":"cli"}]}
</script>
  • A JSON island — no markup, no styling.
  • Layout is automatic; force a direction if you want.
  • Tones carry meaning: accent, ok, warn, risk, info, muted.
  • Edges may carry labels; back edges loop around.

Gotchas

Edit an artifact while a session is open only through the content region and artifact rebuild — the server serves the file as-is on every load.
Inline HTML in steps[].text and timeline[].detail is live; escape literal tags as &lt;tag&gt;.
Artifacts never call the network. Mail them, commit them, open them offline.

FAQ

Do I need pi-intercom?

No. Copy as prompt / Markdown / JSON works without it; intercom only powers Send via Pi.

Where are artifacts written?

<root>/assets/files/, where root is $ARTIFACT_ROOT, the nearest folder with assets/files/, the git root, or the current folder.

How do I get this page's source?

It's examples/showcase.html in the repo; the content region between the kb:content markers is all hand-written, everything else is runtime.

Can I add a component?

Add it to artifacts/runtime/, document it in COMPONENTS.md, bump RUNTIME_VERSION, then artifact rebuild --all.
